## 二、合规风险

### 2.1 上游许可证（P0，开工前定调）

| 项 | 事实 |
|---|---|
| 仓库 `LICENSE` 正文 | **CC BY-NC-SA 4.0**（署名 + **非商业** + 相同方式共享） |
| README 标注 | **MIT** |
| 冲突结论 | **以 LICENSE 正文为准**（README 不具法律效力） |

**对本项目的影响**

- 客户端**不修改上游代码、不链接其代码**，属独立作品，但**引用其名称、图标、文案时**须遵守 **BY（署名）+ NC（非商业）+ SA（相同方式共享）**
- **NC 条款意味着：本项目不得用于商业用途，不得带广告/付费分发** —— 这是产品定位的硬边界，必须让主人知情
- 客户端自身许可证建议：**与上游一致（CC BY-NC-SA 4.0）**，避免 SA 冲突。若坚持用 MIT，需确认未复制上游任何受版权保护的表达（仅调用其 HTTP API 通常不构成衍生）

### 2.2 参考项目许可证（P1）

| 项 | 事实 |
|---|---|
| NipaPlay-Reload | **MIT**，Dart/Flutter，1832 stars |

- MIT **允许**阅读、借鉴、复制代码，但**必须保留原版权声明与许可文本**
- 处置：`CREDITS.md` 列明项目名、作者、许可证、链接；`关于 → 开源许可` 内可查
- **禁止**：复制其图标/插画/字体等资源（这些可能不在 MIT 范围内或另有授权）；复制其配色与图标库（`05` 已定自建 token）

### 2.3 内容与分发（P0）

| 项 | 说明 |
|---|---|
| 数据源 | 客户端**不内置任何采集站/片源名单**，全部由服务端返回 |
| 分发性质 | 客户端只是"播放器 + API 客户端"，不承载内容 |
| 红线 | 不得在 README/Release 中宣传"免费看全网影视"；不得内置破解/去广告绕过付费的功能 |
| 建议 | README 明确写"本客户端需连接自建或自有授权的 MoonTVPlus 实例，不提供任何内容源" |

### 2.4 隐私与密钥（P0）

| 项 | 处置 |
|---|---|
| 服务器地址泄露 | S1 硬编码扫描（`03` 第 5 节）；首次启动地址为空；文档统一 `example.com` |
| 账号密码 | 存 SecureStorage（Keychain / Keystore），不入普通 SharedPreferences |
| 日志 | 禁止打印 cookie/token/password/完整 URL；S4 扫描 |
| keystore | GitHub Secrets 注入，永不入库；S3 扫描 |

## 六、一句话风险总结

> 原生方案把"打包"的风险换成了"前端实现"的风险。真正会让项目失败的不是技术栈，而是三件事：**弹幕源根本没配好**、**鉴权细节没按契约实现**、**工期按薄壳估却按原生做**。这三项都在 P0，开工前必须落地。
