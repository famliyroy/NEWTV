> 前提：原生 Flutter 客户端（`02`），Windows EXE + Android APK，后端零改动。

### 2.2 关键路径（13.5 人日）

```
T-0.1 骨架(0.5) → T-0.2 契约(1) → T-1.1 工程与主题(1.5) → T-1.2 网络与令牌(2)
```

关键路径几乎全部压在**播放器与弹幕渲染**上。含义很直接：

> **想提前看到东西，就先做 T-3.x；想稳，就先做 T-1.2。** 其它任务（首页、追番、设置、收藏）都可并行，不在关键路径上。

## 5. CI 矩阵

| Job | Runner | 触发 | 内容 | 门禁 |
|---|---|---|---|---|
| `test` | ubuntu-latest | PR / push | `flutter analyze` + `flutter test --coverage` | analyze 0 error；domain 覆盖率 ≥ 90% |
| `build-win` | windows-latest | tag / 手动 | `flutter build windows` + Inno Setup | 产物 ≤ 60MB；可执行文件启动自检 |
| `build-apk` | ubuntu-latest | tag / 手动 | `flutter build apk --split-per-abi` | APK ≤ 38MB；`apksigner verify` 通过 |
| `security` | ubuntu-latest | PR / push | S1/S3/S4 敏感信息扫描 | 命中真实域名/密钥即失败 |
| `release` | ubuntu-latest | tag `v*` | 创建 Release、上传产物与 sha256 | 缺产物则失败 |

**`security` job 的扫描规则（必须实现，不是建议）**

```bash
# S1 硬编码地址
! grep -rEn "https?://[A-Za-z0-9.-]+\.(com|xyz|net|cn|io|me)" lib/ \
    | grep -v "example\.com" | grep -v "127\.0\.0\.1" | grep -v "localhost"
# S3 密钥文件
! find . -name "*.jks" -o -name "*.keystore" -o -name "key.properties" | grep -v android/app
# S4 日志泄露
! grep -rEn "(print|logger\.[dibwe])\(.*(cookie|token|password)" lib/
```

## 6. 发布规范

| 项 | 规范 |
|---|---|
| 版本号 | `v主.次.修订`，tag 与 `pubspec.yaml` 一致，不一致则 CI 失败 |
| 分支 | `main` 保护；功能分支 `feat/xxx`；PR 必须过 `test` + `security` |
| Release Notes | 必须含：新增/修复/已知问题/**所需后端最低版本** |
| 产物 | Win：`moontv-client-win-x64.zip` + `.exe` 安装包；Android：3 个 ABI 的 APK；全部附 `.sha256` |
| 禁止 | 不发布 debug 包、不发布未签名包、不发布含真实域名的包 |
