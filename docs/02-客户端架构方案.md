# 02 - 客户端架构方案

> **前提（已定，不再讨论）**
> 1. MoonTVPlus 已部署在主人的服务器上（HTTPS + 登录保护），**作为后端 API 使用，不做任何修改**
> 2. 客户端是**独立的原生 App**，不是 WebView 套壳 —— 因为要复刻 NipaPlay 的界面与交互
> 3. 交付形态：**Windows EXE + Android APK**，同一套代码
> 4. 数据同步不需要额外机制：所有数据在服务端，客户端连本地库都没有
>
> 前置阅读：`01-逆向分析报告.md`（后端能力与接口）、`05-UI交互设计规格.md`（界面）、`06-弹幕全自动加载方案.md`（弹幕）

---

## 1. 为什么是"原生客户端"而不是"WebView 壳"

这是本项目最重要的一次选型，先讲清代价：

| | WebView 薄壳（旧方案，已废弃） | 原生客户端（现方案） |
|---|---|---|
| 实现方式 | 壳里加载 `https://服务器地址` | 自己实现 UI，调后端 API |
| 界面 | **只能用网页版界面**，无法复刻 NipaPlay | 完全可控，按 `05` 文档做 |
| 弹幕全自动 | **做不到**（网页版逻辑在服务端，改不了） | 客户端自己聚合，随便改 |
| 包体 | 6–14 MB | 35–60 MB |
| 工期 | 20 人日 | **48.5 人日** |
| 后端耦合 | 极低（网页改版自动生效） | 中（接口变了要跟着改） |
| 登录 | 用户在网页里登 | 客户端自己管 token |

**根因**：弹幕"全自动加载"和 NipaPlay 风格 UI 都是**前端行为**，但 WebView 壳里前端跑在服务器上。要用壳，就得改后端网页代码并重新部署；要不动后端，就必须自己写前端。

**所以选原生。代价是工期翻倍，收益是需求能真正落地。** 这一点必须让主人知情。

## 2. 技术选型

| 方案 | 语言 | Win | Android | 视频播放 | 弹幕渲染 | 评 |
|---|---|---|---|---|---|---|
| **Flutter + media_kit**（推荐） | Dart | ✓ | ✓ | libmpv，HLS/HEVC/ASS 全支持 | CustomPainter 完全可控 | **✓ 选它** |
| Tauri 2 + React | TS/Rust | ✓ | 实验性 | WebView2 + hls.js，HEVC 弱 | DOM/Canvas 可控 | Android 端不成熟，排除 |
| Compose Multiplatform | Kotlin | ✓ | ✓ | 需自接平台播放器 | Canvas 可控 | 生态新，播放器要写两套 |
| 双原生（WinUI + Compose） | C#/Kotlin | ✓ | ✓ | 各自最优 | 各自实现 | 工作量 ×2，排除 |

**选 Flutter 的三条理由（不是"因为参考项目用它"）**

1. **播放内核统一**：`media_kit`（libmpv 绑定）在 Windows 和 Android 上用同一套 API 播 HLS/m3u8/mp4，无需为两端各写一个解码层。上游视频源大量是 m3u8，这点是刚需。
2. **弹幕渲染可控**：弹幕需要"精确到帧的轨道调度 + 防遮挡"，`CustomPainter` 能直接控制每一条弹幕的位置与生命周期；DOM 方案在 80 条同屏时会明显抖动。
3. **参考项目是 Dart**：NipaPlay-Reload 为 MIT 许可的 Flutter 项目，实现方可以**直接阅读其布局代码**理解玻璃拟态与播放器控制层的做法，沟通成本最低。

**不选 Tauri 的关键原因**：Android 端仍是实验特性，而我们要的是同一套代码出 APK。省下的 30MB 包体不值得冒"Android 打不出包"的风险。

## 3. 分层架构

```
┌─────────────────────────────────────────────────────┐
│ Presentation（UI）                                   │
│  pages/ · widgets/ · theme/          ← 见 05 文档     │
├─────────────────────────────────────────────────────┤
│ State（Riverpod Providers）                          │
│  页面状态、播放状态、弹幕状态、会话状态                  │
├─────────────────────────────────────────────────────┤
│ Domain（纯逻辑，零依赖，全部要有单测）                   │
│  models/ · episode_matcher · danmaku_merger · title_cleaner │
├─────────────────────────────────────────────────────┤
│ Data（数据获取与持久化）                               │
│  api/ (Dio) · repositories/ · db/ (drift) · cache/    │
├─────────────────────────────────────────────────────┤
│ Core（横切能力）                                      │
│  network/ (拦截器) · auth/ (令牌) · config/ (服务器地址) │
│  player/ (media_kit 封装) · utils/ · logging/         │
└─────────────────────────────────────────────────────┘
```

**分层铁律**
- `domain` 层**禁止** import `dio` / `flutter` 之外的东西，更不能碰 UI。它的价值就是"可以脱离 App 跑测试"。
- UI **禁止**直接调 `Dio`，必须走 repository。
- 所有后端接口路径**只在** `data/api/endpoints.dart` 出现一次，禁止散落。

## 5. 鉴权：本方案最容易翻车的一环

后端的鉴权不是简单的 Bearer Token，而是 **Cookie + HMAC 签名 + 双令牌**（详见 `01` 第 7 节）。客户端必须完整复刻浏览器行为。

### 5.1 机制

```
POST /api/login  {username?, password}
  → 200 {ok:true, token?, auth?}
  → Set-Cookie: auth=<HMAC 签名的 JSON>   ← 后续所有请求的唯一凭证
```

`auth` cookie 内含：`username / role / signature / timestamp / tokenId / refreshToken / refreshExpires`

`middleware` 的判定顺序：
1. cookie 不存在 → API 返回 **401**
2. refreshToken 过期（对比 `refreshExpires`）→ 401，**必须重新登录**
3. accessToken 过期（`now - timestamp > ACCESS_TOKEN_AGE`）→ 401 `Access token expired`，**可用 refresh 续期**
4. 签名校验失败 → 401

### 5.2 客户端实现要点

```dart
// auth_interceptor.dart —— 骨架，不是完整代码
onError: (err, handler) async {
  if (err.response?.statusCode != 401) return handler.next(err);
  if (err.requestOptions.extra['retried'] == true) return handler.next(err); // 只重放一次

  final ok = await sessionManager.refresh();      // POST /api/auth/refresh，带 cookie
  if (!ok) {
    appRouter.go('/login');                       // 续期失败 → 回登录页
    return handler.next(err);
  }
  final req = err.requestOptions..extra['retried'] = true;
  final res = await dio.fetch(req);               // 重放原请求
  return handler.resolve(res);
}
```

**四条硬性要求**

| # | 要求 | 原因 |
|---|---|---|
| 1 | 持久化**整个 CookieJar**，不是只存 token | middleware 只认 cookie `auth` |
| 2 | 401 只重放 **1 次** | 防死循环打爆后端（后端有 fail2ban，会被封 IP） |
| 3 | 并发 401 时**只发一次 refresh**，其余请求排队等待 | 否则 N 个请求触发 N 次 refresh，令牌互相覆盖 |
| 4 | refresh 失败立即清 cookie 并跳登录，不静默重试 | 已被登出/封禁时重试无意义且有害 |

### 5.3 特殊接口的免鉴权清单

`middleware` 已放行（客户端**无需登录即可调用**）：

```
/api/login  /api/register  /api/auth/refresh
/api/server-config            ← 用于首次连接的"测试连接"按钮
/api/proxy-m3u8  /api/cms-proxy  /api/proxy
/api/theme/css  /api/tvbox/subscribe
```

> **`/api/proxy-m3u8` 免鉴权是本项目的关键便利**：播放内核（libmpv）发起的分片请求天然带不上我们的 cookie，若该接口需要鉴权，就必须给内核注入 header（可行但脆弱，HLS 分片重定向容易丢 header）。现在只需把完整代理 URL 交给内核即可。
>
> 前提：服务端**未设置** `NEXT_PUBLIC_PROXY_M3U8_TOKEN`。若主人设置了，客户端需在设置页提供"播放令牌"输入项并拼到 `&token=`。

## 6. 播放链路

```
详情页点击第 12 集
   │
   ├─ 1. GET /api/detail?id=&source=            → 拿到该集原始播放地址 rawUrl
   │
   ├─ 2. 组装代理地址：
   │     {base}/api/proxy-m3u8
   │       ?url={urlEncode(rawUrl)}
   │       &source={sourceCode}
   │       &adblock=true                 （默认开，服务端做广告分片过滤）
   │       &proxySegments=false          （默认关；开启则所有 ts 分片也走代理，流量翻倍）
   │       [&token=xxx]                  （仅当服务端配置了播放令牌）
   │
   ├─ 3. media_kit 打开该 URL
   │     注意：必须设 UA，部分源校验
   │
   ├─ 4. 起播成功 → 并行启动：
   │     ├─ 弹幕聚合（06 文档，不阻塞）
   │     ├─ 上报播放记录 POST /api/playrecords
   │     └─ 预取下一集 detail（省一次点击等待）
```

**必须处理的坑**

| 坑 | 处理 |
|---|---|
| 原始地址含 `#` 或中文 | 必须 `Uri.encodeComponent` 整体编码 |
| 部分源返回 m3u8 内含相对路径 | 交给服务端代理处理，客户端不要自己拼接 |
| 直播源（`/api/live`） | 同为 m3u8，走同一代理，不区分 |
| 多集连播 | 播完自动下一集；用**同一个 player 实例** `open()`，不要销毁重建（避免黑屏闪烁） |
| 硬解失败 | media_kit 可切 `vo=gpu` / `hwdec=auto-safe`；设置中提供"硬解/软解"开关 |
| 切集时弹幕残留 | 切集前 `danmakuController.clear()`，再按新集重新聚合 |

## 7. 数据与缓存

服务端才是数据源，客户端只做"加速"与"离线兜底"。

| 数据 | 位置 | 有效期 |
|---|---|---|
| 登录 cookie | SecureStorage | 直到 refresh 过期 |
| 服务器地址 | SecureStorage | 持久 |
| 设置项 | SharedPreferences | 持久 |
| 搜索结果 | 内存（Riverpod） | 5 分钟 |
| 详情 | SQLite | 24 小时（海报 URL 会过期，只缓存元数据） |
| 播放历史 / 收藏 | **不缓存**，直接读接口 | — 多端一致性优先 |
| 弹幕（合并后） | SQLite | 7 天 |
| 图片 | `cached_network_image` 磁盘缓存 | 30 天 |

**多端同步**：因为历史/收藏/进度全部在服务端（kvrocks），客户端**不需要任何同步逻辑**，每次进页面拉取即可。这是"后端已部署"带来的最大红利，不要画蛇添足做本地同步。

## 8. 配置与安全（硬约束）

| # | 约束 | 检查方式 |
|---|---|---|
| S1 | **代码中不得出现任何真实服务器地址/域名/IP** | CI: `grep -rEi "https?://[a-z0-9.-]+\.(com\|xyz\|net\|cn)" lib/` 仅允许 `example.com` 与本地回环 |
| S2 | 服务器地址只能由用户输入，存 SecureStorage | code review |
| S3 | Release 包不得包含 `.env` / keystore / 证书私钥 | CI 检查产物内文件清单 |
| S4 | 日志不得打印 cookie、token、password、完整视频 URL | CI: `grep -rn "print(.*cookie\|logger.*token"` |
| S5 | 允许 http（局域网自建），但 UI 必须警示"非加密连接" | 手动 |
| S6 | 不内置任何第三方数据源/采集站名单 | code review |
| S7 | `CREDITS.md` 必须含 MoonTVPlus(CC BY-NC-SA 4.0) 与 NipaPlay-Reload(MIT) 声明 | CI 检查文件存在 |

```
Flutter build windows --release
```

```
Flutter build apk --release --split-per-abi
产物：app-arm64-v8a-release.apk（主）/ armeabi-v7a / x86_64
签名：keystore 由 GitHub Secrets 注入，禁止入库
minSdk 24 (Android 7.0) / targetSdk 34
```

**体积预算**：arm64 单包 ≈ **28–38 MB**。

### 9.3 CI（GitHub Actions）

```yaml
# .github/workflows/build.yml 结构，细节在 03 的 T-6 任务
jobs:
  test:      # flutter analyze + flutter test（domain 覆盖率门槛 90%）
```

**发布纪律**

- 不发布 debug 包、不发布未签名包

## 10. 版本兼容与降级

后端能力会变（主人可能升级镜像），客户端必须"探测而非假设"。

```dart
// 首次连接时探测一次
GET /api/server-config   →  { SiteConfig: {...}, ... }
```

| 探测结果 | 客户端行为 |
|---|---|
| 200 + 合法 JSON | 正常使用，记录 `serverFingerprint` |
| 200 但缺 `SiteConfig` | 仍可用，但隐藏"推荐/榜单"等依赖配置的模块 |
| 404 | 提示"该地址不是 MoonTVPlus 服务"，停在配置页 |
| 5xx | 提示"服务端异常"，允许"仍要继续"（可能只是某个模块挂了） |

**向后兼容承诺**：客户端只依赖本文与 `01` 第 13 节列出的接口。若后端升级导致这些接口变化，客户端需在一个版本内适配，并在 UI 上给出"服务端版本过新，请更新客户端"的明确提示，而不是白屏。

## 12. 明确不做（防止范围蔓延）

| 不做 | 原因 |
|---|---|
| 内嵌服务端 / 离线播放库 | 后端已在服务器，本地库是另一套产品 |
| 下载/离线缓存视频 | 版权风险 + 工作量翻倍，v2 再议 |
| Emby/Jellyfin/SMB 挂载 | 那是 NipaPlay 的定位，不是我们的 |
| 多播放内核抽象 | 一个 media_kit 够用，抽象是负债 |
| 自建弹幕服务 | 弹幕源由服务端配置决定；客户端只负责聚合 |
| 网页版 / iOS / TV 版 | v1 只出 Windows + Android |
| 账号体系（注册/多用户） | 直接用后端现有的单密码/多用户登录 |

## 13. 与后端的接口契约索引

完整契约见 `01-逆向分析报告.md` 第 13 节。客户端**只允许**调用以下接口：

```
认证   POST /api/login · POST /api/auth/refresh · POST /api/logout
探测   GET  /api/server-config
搜索   GET  /api/search?q= · GET /api/search/suggestions
详情   GET  /api/detail?id=&source=
播放   GET  /api/proxy-m3u8?url=&source=&adblock=
弹幕   GET  /api/danmaku/search?keyword= · POST /api/danmaku/match
       GET  /api/danmaku/episodes?animeId= · GET /api/danmaku/comment?episodeId=
用户   GET  /api/favorites · GET  /api/searchhistory · POST /api/playrecords
番剧   GET  /api/bangumi
推荐   GET  /api/douban-recommendations · GET /api/advanced-recommendation
```

清单外的接口一律不用——每多用一个是多一个会变的依赖。
