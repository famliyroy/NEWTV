> 等级：**P0** 可终止项目 ｜ **P1** 返工 >3 人日或影响发布 ｜ **P2** 可局部规避 ｜ **P3** 观察项

## 一、技术风险

| ID | 风险 | 等级 | 概率 | 影响 | 早期信号 | 缓解 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | **默认域名泄露**：把服务器地址写进公开仓库或公开 Release | **P0** | **高** | 高 | 仓库 `grep` 到真实域名 | 公开版构建不含任何地址；私有版走 Secret 注入且不公开；CI 加 `strings` 扫描门禁；文档统一 `example.com` |
| R2 | WebView2 未安装 → 打开白屏 | **P0** | 中 | 高 | 用户反馈"双击没反应" | 启动检测运行时，给出官方安装链接与说明；Win11 自带，Win10 1903+ 多数自带 |
| R3 | 登录态不持久，每次启动都要重登 | P1 | **高** | 中 | 重启后跳 `/login` | Android `CookieManager.flush()`；Tauri 确认 WebView2 用户数据目录可写且未被清理；纳入验收项 |
| R4 | 服务器域名/证书变更导致客户端全部失效 | P1 | 中 | 高 | 证书过期、换域名 | ① 客户端地址可改，且有"服务器无法连接"友好页；② 证书自动续期监控；③ 发布说明提示换域名时如何改 |
| R5 | 外链劫持：点源站详情把壳导航走，回不来 | P1 | **高** | 中 | 用户"点了广告就再也回不去" | 域名白名单：仅主站内开，其余交系统浏览器；补"返回主页"入口 |
| R6 | Service Worker 缓存旧版，服务端更新后客户端仍是老界面 | P1 | 高 | 中 | 清缓存才恢复 | 提供「清除缓存」按钮；版本号变化时自动提示刷新 |
| R7 | 视频全屏在 WebView2 / Android WebView 中黑屏或无法退出 | P1 | 中 | 中 | 全屏后无画面 | Tauri 接管窗口全屏；Android 复用上游 `customView` 回调并补横屏切换 |
| R8 | Tauri 学习曲线导致 M1 延期 | P1 | 中 | 中 | W1 末仍未出可运行 exe | 提前跑通官方模板；保留 Electron 回退分支（切换成本约 2 人日） |
| R9 | 服务端单点故障：服务器挂了客户端全废 | P1 | 低 | 高 | 站点 502 / 超时 | 客户端显示"服务器不可达 + 重试 + 改地址"；文档说明自建可用性责任 |
| R10 | Android 后台被系统回收，播放中断 | P2 | 高 | 低 | 切后台回来重载 | v1 明确不支持后台播放；恢复前台自动续播（依赖上游） |
| R11 | 下载行为在两端不一致（桌面走系统下载器、Android 走 DownloadManager） | P2 | 中 | 低 | 下载按钮无反应 | 两端分别实现并纳入测试；不支持的场景直接隐藏入口 |
| R12 | 上游改版影响壳层（路由结构、全屏实现变化） | P2 | 中 | 中 | 上游发新版后壳异常 | 客户端不依赖具体路由，只依赖根地址；每次上游大版本升级跑一遍冒烟 |
| R13 | 签名密钥泄露 → 他人可发布冒名更新 | P1 | 低 | 高 | 出现非本人发布的包 | keystore 仅存 GitHub Secrets；`docs/signing.md` 不写任何密钥值；泄露即换包名重发 |
| R14 | 用户填 `http://` 地址导致超分等能力不可用 | P2 | 中 | 低 | 超分按钮灰置 | 配置页提示"https 才能用超分"；不阻断使用 |
| R15 | 扫码协议将来变更导致老客户端读不了新码 | P3 | 低 | 低 | 新码扫不出 | 协议带 `v` 字段，服务端/桌面生成时保持向后兼容 |

## 二、合规风险

### 2.1 许可证（P1）

| 事实 | 说明 |
| --- | --- |
| 仓库 `LICENSE` 正文 | **CC BY-NC-SA 4.0**（署名 + 非商业 + 相同方式共享） |
| `README.md` 却标注 | `MIT` |
| 二者关系 | 互斥，以文件正文为准更安全 |

**对本项目的影响**（比内嵌方案轻很多）：

| 情形 | 是否构成衍生 | 约束 |
| --- | --- | --- |
| 客户端只做壳、不改上游代码 | 否 | 主要受「署名」约束；建议 README 显著位置署名并链回上游 |
| 引用上游图标 / 文案 / `libbitsub` | 是（部分） | 该部分须遵守 **BY-NC-SA**，且不得用于商业 |
| 未来若修改上游代码 | 是 | 整个修改版须同协议开源、非商业 |

**建议**：客户端代码自选许可证（MIT/Apache-2.0 均可），但必须：
1. README 顶部写明「本客户端不含任何影视内容，需配合自建 MoonTVPlus 服务端使用」；
2. 保留上游项目名、链接与作者署名；
3. 若复用上游图标，单独注明其许可；
4. 全程非商业（不卖、不内置广告、不做会员）。

> 本文只做技术性提示，不构成法律意见。正式发布前如有商业打算，请咨询专业人士。

### 2.2 内容与分发（P0）

客户端只是壳，风险主要来自"壳 + 已有服务器"的组合被理解为"开箱即用的影视应用"。

| 红线 | 要求 |
| --- | --- |
| 不内置数据源 | 客户端不含任何源配置；服务端配置由使用者自理 |
| 不公开演示地址 | README 不贴可访问实例，不截图真实域名 |
| 不引导传播 | 措辞避免"一键看全网""免费影视"等表述 |
| 保留免责声明 | README + 关于页两处 |
| 不上架应用商店 | 规避审核与账号风险 |
| 不预置账号 | 客户端不保存明文密码，登录由 WebView 承担 |

### 2.3 第三方资源（P2）

- 打包时生成 `THIRD-PARTY-NOTICES.txt`（Tauri 依赖、Android 依赖）；
- 图标若使用第三方素材，须确认授权（建议自绘或使用 CC0）；
- 排除 GPL/AGPL 依赖，避免传染性条款。

## 三、执行风险

| ID | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R16 | 需求漂移：从"打包客户端"变成"改功能/加功能" | P1 | 明确边界（见 03 文档 §7）；业务需求一律推给上游或延后 |
| R17 | 无干净 Windows 机器，安装与兼容验证不充分 | P1 | 至少 Win10 21H2 + Win11 各一台；用虚拟机快照复现"干净环境" |
| R18 | 单人开发时 Android 支线被拖到最后 | P2 | 先出桌面版自用，再补 Android；不追求同期发布 |
| R19 | Release 后大量"装完要填地址，不会用"的反馈 | P1 | README 首屏 + 安装文档 + FAQ 三处讲透；配置页放"什么是服务器地址"的说明 |
| R20 | 服务器被扫描/攻击导致服务不可用 | P2 | 保持登录保护开启、关闭公网注册、面板端口不暴露 |

## 四、处置节奏

```
M0  ── R1（域名泄露）、R13（密钥）定规则，写进 CI 门禁
M1  ── R2（WebView2）、R3（登录态）、R5（外链）首批验证
M2  ── R3、R6、R7（缓存/全屏）在真机验证
M3  ── R2、R3、R5、R9 全量回归；R17 环境就绪
M4  ── R1 最终扫描（strings + 全文 grep）、R19 文档复查、第三方声明
```

## 五、开工前检查表（30 分钟可完成）

- [ ] 确认公开仓库**不含**任何真实域名、服务器 IP、账号密码
- [ ] 已准备 Win10 + Win11 各一台（或虚拟机）用于安装验证
- [ ] Android 有至少一台真机，keystore 已生成并只存 Secrets
- [ ] 已确定客户端许可证（建议 MIT/Apache-2.0）并保留上游署名
- [ ] 已确认不内置源、不上架商店、不公开演示地址
- [ ] 已确认服务端证书续期正常（当前证书有效期至 2026-12-31）
- [ ] 已想清楚"服务器不可达"时客户端该显示什么
