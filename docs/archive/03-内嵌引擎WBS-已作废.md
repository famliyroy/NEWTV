## 5. GitHub 文档与发布规范

### 5.1 仓库文档结构

```
README.md                      # 首屏：是什么 / 一张图 / 3 步跑起来 / 下载入口 / 免责声明
docs/
├─ 01-逆向分析报告.md          # 本套
├─ 02-打包架构方案.md
├─ 03-开发计划与任务分解.md
├─ 04-风险登记与合规审查.md
├─ adr/                        # 架构决策记录（许可证、仓库策略、引擎选型）
├─ build.md                    # 本地构建（Windows/macOS/Linux 三平台前置条件）
├─ desktop.md                  # 桌面端使用与故障排查（端口/杀软/数据目录/日志位置）
├─ android.md                  # APK 安装、地址配置、扫码、常见问题
├─ faq.md                      # "为什么需要服务器""为什么装完是空的"
├─ signing.md                  # 签名与密钥管理（不含任何密钥内容）
└─ test-plan.md                # 冒烟用例与验收清单
```

### 5.2 README 首屏结构（必须包含）

1. 一句话定位 + 架构图（复用 02 文档 §2）。
2. 下载区：Latest Release 的 exe / apk 直链。
3. 3 步上手：装 EXE → 首启向导 → 填数据源。
4. 与上游关系：基于 `mtvpls/MoonTVPlus v226.1.0`，明确"本项目只做打包与壳层，业务功能归上游"。
5. **免责与许可**：LICENSE 冲突说明、不内置内容源、仅供个人学习使用。

### 5.3 发布流程

```
1. 更新版本号（package.json / VERSION.txt / android versionCode 三处一致）
2. 更新 CHANGELOG（新增/修复/已知问题 三段）
3. git tag vX.Y.Z → push
4. CI：build-desktop（矩阵 win-x64）→ build-android（arm64/v7a）→ release 草稿
5. 人工验收清单（§6）逐项打勾
6. 发布 Release（附产物哈希 SHA256）
7. 同步文档中"当前支持版本"
```
