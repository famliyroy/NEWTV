# 07 - AI 开发交接指南

> **本文件是给接手开发的 AI 代理 / 开发者的执行契约。**
> 首次接手请**按顺序读**：本文 → `03`（做什么、怎么验收）→ `02`（架构与技术选型）→ `05`（界面）→ `06`（弹幕）→ `01`（后端接口）。
> 本文优先级最高：**任何文档冲突，以本文为准；任何本文未授权的"优化"，都不要做。**

---

## 1. 一句话目标

为**已在服务器运行的 MoonTVPlus** 写一个**原生 Flutter 客户端**（Windows EXE + Android APK），界面参考 NipaPlay-Reload 的设计语言，弹幕必须**多源自动加载、零点击**，后端不改一行代码。

---

## 2. 开始前必须向主人确认的 6 件事

**不要在信息不全的情况下开始写代码。** 以下缺任何一项，就先问，不要假设。

| # | 需要确认 | 为什么不能假设 |
|---|---|---|
| 1 | 服务器地址（含协议） | 决定 HTTPS/HTTP、证书处理、WebGPU 类能力是否可用 |
| 2 | 登录方式（仅密码 / 用户名+密码） | 决定登录页字段与 `/api/login` 请求体 |
| 3 | 后端是否设置了 `NEXT_PUBLIC_PROXY_M3U8_TOKEN` | 决定是否需要在设置页加"播放令牌"项 |
| 4 | 后端 `SiteConfig.DanmakuApiBase` 是否已配置可用弹幕源 | **内置源已 503 不可用**；未配置则弹幕全程无数据，必须提前告知 |
| 5 | GitHub 仓库名与组织 | 影响 CI 徽章、Release 链接、包名 |
| 6 | Android 包名（如 `com.example.moontvclient`）与签名 keystore 由谁提供 | 包名一旦发布不可更改 |

> 附带确认：是否需要 Android TV 版本。v1 计划**不含**，若要则 +3 人日。

## 3. 绝对禁止（触碰即返工）

| # | 禁止事项 | 原因 |
|---|---|---|
| N1 | **在代码/资源/注释/默认值中写入任何真实服务器地址、域名、IP、密码** | 仓库要公开；泄露即等于公开主人的私人站点 |
| N2 | 把 keystore、`.env`、`key.properties` 提交进仓库 | 签名密钥泄露不可撤回 |
| N3 | 修改后端（MoonTVPlus）任何代码 | 后端是线上实例，改动会波及现有用户 |
| N4 | 用 WebView 套壳替代原生实现 | 需求（NipaPlay 界面 + 全自动弹幕）在壳内无法实现 |
| N5 | 引入 `chewie` / `better_player` / `flutter_video_player` 等封装播放器 | 无法满足控制层与弹幕叠加需求，且与 media_kit 冲突 |
| N6 | 在日志中打印 cookie / token / password / 完整视频 URL | 用户日志被截图/上报即泄露 |
| N7 | 用"随便取第一集"作为弹幕集数兜底 | 错集弹幕比没有弹幕更糟（`06` 第 5 节 P4） |
| N8 | 弹幕加载失败时弹模态框或阻断播放 | 弹幕是增强功能（`06` 第 8 节） |
| N9 | 自创后端不存在的接口，或调用 `01` 第 13.8 节禁用的接口 | 必然 404 或引入脆弱耦合 |
| N10 | 照抄 NipaPlay-Reload 的配色与图标库 | 会变成"换皮"，`05` 第 1 节已定 token |
| N11 | 跳过单元测试直接写实现（尤其弹幕三件套） | 错集/错并难以被用户描述清楚，只能靠测试兜住 |
| N12 | 一次性提交整个 App 再交给主人验收 | 必须按里程碑分批交付，让主人尽早看到可运行版本 |

## 4. 执行协议（每个任务都照此走）

```
① 读任务：在 03 中找到任务 ID，抄下"交付物"与"验收标准"到工作笔记
② 先查契约：接口字段以 01 第 13 节 + test/fixtures 为准；缺字段就先抓真实响应
③ 写测试：domain 层与纯函数任务，先写失败测试（T-4.1 强制）
④ 实现：最小可用实现，不顺手重构无关代码
⑤ 自验：逐条跑"验收标准"，贴出命令与实际输出（不是"应该没问题"）
⑥ 记录：更新 CHANGELOG 对应条目
⑦ 提交：一个任务一个 commit，message 用 `feat(player): T-3.2 播放页两段式控制层`
⑧ 汇报：任务 ID + 做了什么 + 验收结果 + 遗留问题（三段，别写长篇）
```

**汇报模板（直接照填）**

```
任务：T-3.2 播放页 + 两段式控制层
状态：完成 / 部分完成（说明卡点）
验收：
  - 3 秒无操作只剩进度条 —— 通过（截图 x）
  - 点击画面切换控制层 —— 通过
  - 拖拽误差 < 1s —— 实测 0.4s
遗留：全屏切换在副屏上有 100ms 黑闪，已记入 T-5.1
```

## 5. 技术硬约束（违反会导致返工）

### 5.1 网络与鉴权
- 持久化**整个 CookieJar**，不是只存 `token` 字段
- 401 只重放 **1 次**；并发 401 **单飞 refresh**
- refresh 失败立即清 cookie 跳登录，不静默重试
- 后端有 fail2ban：登录失败重试必须有退避，禁止循环重试

### 5.2 播放
- 播放地址**必须**经 `/api/proxy-m3u8` 代理，不得直连原始地址（防盗链/广告过滤都靠它）
- `url` 参数必须整体 `Uri.encodeComponent`
- 切集时复用同一个 player 实例（`open()` 而非销毁重建），否则黑屏闪烁
- 切集前必须 `danmakuController.clear()`

### 5.3 弹幕
- 加载与播放**并行**，绝不阻塞起播（A5：延迟差 < 200ms）
- 并发上限 6、单源超时 8s、总预算 12s、单源上限 3000 条、总量上限 12000 条
- 去重键 = `0.1s 精度时间 + 去空白文本`，**不能用弹幕 ID**（跨源不可比）
- 全局关闭弹幕后**不发任何弹幕请求**（A10）
- 用户手动选过源的剧集，记忆优先于自动（A9）

### 5.4 UI
- 玻璃层必须三件套齐全：`BackdropFilter` + 半透明填充 + 1px 描边；最多叠 2 层
- 先做暗色主题，再调亮色（亮色是玻璃拟态的弱项）
- 每页必须有空态与非 happy-path 的错误态
- 动效"减弱"开关必须真实降低转场时长

### 5.5 工程
- 接口路径只在 `data/api/endpoints.dart` 出现一次
- `domain/` 层禁止 import UI 与 Dio
- 任何新增依赖都要在 PR 说明里写理由；不引入功能重叠的包

## 6. 常见陷阱清单（前人踩过，别再踩）

| 陷阱 | 表现 | 正解 |
|---|---|---|
| 只存 token 不存 cookie | 所有接口 401，登录看似成功 | 持久化 CookieJar |
| 401 无限重放 | 后端 429/封 IP | 只重放 1 次 + 退避 |
| 并发 refresh | 令牌互相覆盖，随机掉登录 | 加锁单飞 |
| 播放直连原始 m3u8 | 403 / 无限缓冲 | 走 `/api/proxy-m3u8` |
| URL 未编码 | 含中文或 `#` 的源播不了 | `Uri.encodeComponent` |
| 以为 ep 有集号字段 | 匹配全错、编号错位 | 解析 `episodeTitle`（`06` 第 5 节） |
| 拿弹幕 ID 去重 | 去重率 0（跨源 ID 全不同） | 用时间+文本 |
| 每帧遍历全部弹幕 | 播放掉帧到 20fps | 二分查找时间窗 |
| 弹幕阻塞起播 | 点集到出画面要 10s+ | 并加载，先播后补弹幕 |
| 详情页一次渲染 500 个 chip | 卡死 | `ListView.builder` |
| Android 后台无前台服务 | 息屏即断 | `mediaPlayback` 前台服务 |
| 用 `print` 调试后忘记删 | CI security job 失败 | 统一 `logger`，发布前扫描 |
| 把测试用的真实地址写进默认值 | 仓库泄露 | 首次启动必须为空 |

## 7. 分批交付计划（务必遵守）

**不要等全部做完再交。** 每批结束都请主人实际安装验证。

| 批次 | 内容 | 预计 | 主人要做的验证 |
|---|---|---|---|
| 第 1 批 | M0 + T-1.1~T-1.4（骨架、网络、配置、登录） | 7.5 人日 | 装到电脑与手机，能登录，能列出搜索结果 |
| 第 2 批 | T-2.3 T-2.4 T-3.1 T-3.2（搜索、详情、播放） | 7.5 人日 | **能看片**——这是最关键的一次验证 |
| 第 3 批 | T-4.1~T-4.5（弹幕全自动） | 8 人日 | 零点击出弹幕，多源生效 |
| 第 4 批 | 其余页面与双端打磨（含 T-1.5/1.6、T-2.1/2.2/2.5/2.6/2.7、T-3.3~3.7、WP5） | 21.5 人日 | 完整体验，提修改意见 |
| 第 5 批 | CI 与发布（WP6） | 4 人日 | 从 Release 页下载安装 |

> 合计 7.5 + 7.5 + 8 + 21.5 + 4 = **48.5 人日**，与 `03` 一致。

> 第 2 批结束时如果"能看片"，项目就算成功了一半。**如果 media_kit 在你的目标机型上播不了，立即停下汇报，不要硬扛**——那意味着要换内核（如 Android 用 ExoPlayer 封装），属于方案变更，必须由主人决策。

## 8. 遇到歧义时的处理顺序

```
1. 先查文档：03 → 02 → 05 → 06 → 01，按此顺序
2. 文档有明确答案 → 直接做，不要问
3. 文档没写但影响小（间距、文案措辞） → 自行决定，记入 CHANGELOG
4. 文档没写且影响架构/接口/工期 → **停下来问**，给 2 个方案 + 推荐
5. 发现文档写错了 → 先按文档做，同时明确指出错误与依据（源码/真实响应），等确认后再改文档
```

**判断标准**：改动会影响到"主人看到的东西"或"工期评估"的，属于第 4 类，必须问。

## 9. 完成定义（DoD）

一个任务只有同时满足以下 5 条才算完成：

1. 代码通过 `flutter analyze`（0 error）
2. 有对应测试且通过（domain 层必须有）
3. `03` 中该任务的"验收标准"逐条实测通过，并贴出证据
4. 无 `// TODO` 遗留（有就写成任务放进 `03`）
5. 已更新 CHANGELOG

**整个项目**的 DoD 见 `03` 第 7 节验收清单（功能 / 弹幕 A1–A10 / UI U1–U10 / 工程 5 项）。

把下面内容原样作为 `AGENTS.md` 提交，这样后续任何 AI 接手都会先读到约束：

```markdown

## 必读

## 铁律
```
